# Policy

Policy selects upstreams, public tool names, path protections, limits, task
resolver metadata, and audit behavior. Built-in tool schemas are not sourced
from policy files; they come from the contract registry and are documented in
[Tool Contracts](tools.md).

Runtime configuration selects policy in one of two ways:

```text
server.mode   -> built-in policy from policies/read-only.yaml or policies/dev.yaml
server.policy -> explicit policy file
```

`server.mode` and `server.policy` are mutually exclusive. Policy files can use
`extends` to merge a base policy.

Important fields:

- `upstreams`: named MCP servers using `stdio`, `streamable-http`, or the built-in `local-task-runner`.
- `tools`: ChatGPT-facing tools. Types are `builtIn`, `passThrough`, and `workflow`.
- `workspace.protected`: path deny patterns enforced by built-ins and pass-through path policies.
- `limits`: output, HTTP body, tree/search/read/change/task/manual, and rate limits.
- `taskBundles`: controls which discovered project task families are reported as candidates.
- `editMode`: defaults to `single`; batch edit mode is opt-in.
- `hostRisk`: manual-first routing defaults for raw shell-shaped work, unknown tasks, large diffs, and delete-heavy changes.
- `taskCatalog`: resolver capability metadata. It does not make commands runnable.
- `audit`: JSONL audit logging switch and retention options.

Policy files use `version: 3`. `passThrough` tools must declare an
`inputPolicy` with either `pathFields` or explicit `noPathInput: true`;
protected-path handling defaults to `deny`. Optional pass-through tools are
published while unavailable only when they declare local input and output
schemas. `workflow` tools must declare fixed `steps`, an input schema, an
output schema, and at least one example.

The editor schema at `policies/schema.json` is generated by
`npm run policy:schema`. Tool contracts and examples are generated by
`npm run generate:tools`.
